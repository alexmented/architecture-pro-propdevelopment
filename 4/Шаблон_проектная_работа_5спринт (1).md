| Роль  | Права роли | Группы пользователей |
| --- | --- | --- |
| devops-role | Full access на pods, services, configmaps, deployments, replicasets. Действия: get, list, watch, create, update, patch, delete. Доступ к логам pods. | devops-group |
| developer-role | Read-only на pods, services, configmaps, deployments, replicasets. Действия: get, list, watch. Доступ к логам pods. | app-developers |
| secret-reader-role | Read-only на secrets во всех namespace. Действия: get, list, watch. | secret-readers |
| prod-devops-role | Full access на pods, services, configmaps, deployments, replicasets. Действия: get, list, watch, create, update, patch, delete. Доступ к логам pods. | devops-group |
| prod-developer-role | Read-only на pods, services, configmaps, deployments, replicasets. Действия: get, list, watch. Доступ к логам pods. | app-developers |


### 1. Проверка Developer (alex.ivanov@company.com) в Development

**Проверка прав на чтение (должны работать):**
```bash
kubectl auth can-i get pods --as=alex.ivanov@company.com -n development
kubectl auth can-i list deployments --as=alex.ivanov@company.com -n development
kubectl auth can-i watch services --as=alex.ivanov@company.com -n development
kubectl auth can-i get pods/log --as=alex.ivanov@company.com -n development
```

**Проверка прав на запись (должны быть запрещены):**
```bash
kubectl auth can-i create pods --as=alex.ivanov@company.com -n development
kubectl auth can-i delete deployments --as=alex.ivanov@company.com -n development
kubectl auth can-i update services --as=alex.ivanov@company.com -n development
```

**Проверка доступа к secrets (должен быть запрещен):**
```bash
kubectl auth can-i get secrets --as=alex.ivanov@company.com -n development
kubectl auth can-i list secrets --as=alex.ivanov@company.com -n development
```

### 3. Проверка Security Admin (security.admin@company.com)

**Проверка доступа к secrets (должен работать):**
```bash
kubectl auth can-i get secrets --as=security.admin@company.com -n development
kubectl auth can-i list secrets --as=security.admin@company.com -n development
kubectl auth can-i watch secrets --as=security.admin@company.com -n development
kubectl auth can-i get secrets --as=security.admin@company.com -n production
```

**Проверка что нет прав на изменение secrets:**
```bash
kubectl auth can-i create secrets --as=security.admin@company.com -n development
kubectl auth can-i delete secrets --as=security.admin@company.com -n development
```
